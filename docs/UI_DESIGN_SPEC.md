# PrepTracker UI Design Specification

Screen-level specifications and the lightweight design system for the mobile redesign proposed in
[UX_AUDIT.md](UX_AUDIT.md). Everything here is a proposal awaiting approval; nothing has been
implemented. Mockup sources for every screen are in `docs/mockups/` (one `.dc.html` per screen,
generated by `build-artboards.mjs` from the same token values listed below).

Design principle carried through every screen:

> Daily actions should take seconds. Planning actions can take longer.

---

## 1. Design system

### 1.1 Typography

System font stack, deliberately: `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto,
system-ui, sans-serif`. The current CSS references an undefined `--font-geist-sans` variable and
already falls back to this; make it explicit. A system face renders instantly, matches the OS
text-size setting, and reads like a utility, which is what a kitchen tool should feel like.

| Style | Size / line | Weight | Use | Notes |
| --- | --- | --- | --- | --- |
| Page title | 22 / 28 | 600 | Header h1 | letter-spacing −0.01em |
| Hero title | 22 / 28 | 600 | Next-meal name | same as page title on purpose |
| Section heading | 13 / 16 | 600 | "MEALS", "SUPPLEMENTS" | uppercase, tracking 0.04em, muted |
| Meal title | 17 / 22 | 600 | Meal rows and cards | |
| Primary metric | 28 / 32 | 600 | "1.5 / 4.0 L", "12 items remaining" | tabular numerals |
| Body | 15 / 22 | 400 | Ingredient rows, descriptions | |
| Secondary | 13 / 18 | 400 | Times, hints, captions | muted colour |
| Label | 12 / 16 | 500 | Chip text, nav labels, eyebrows | never below 12 px anywhere |
| Button | 16 / 20 | 600 | All buttons | |

Numbers: `font-variant-numeric: tabular-nums` on every element that shows a quantity, time or
count, so "175 g" and "225 g" align in columns and countdowns do not jitter. Amounts are written
as "70 g oats" in the hero (amount first, because you weigh first) and "Oats … 70 g" in rows
(name first, amount right-aligned) so that both scan well.

All sizes are in rem so the OS text-size setting scales them. The layouts below are specified to
survive 160 % text without horizontal overflow (rows wrap, rings are not used).

### 1.2 Spacing scale

4-pt scale: 4, 8, 12, 16, 20, 24, 32, 40.

| Token | Value | Use |
| --- | --- | --- |
| gutter | 16 | Page side padding at every width |
| card-pad | 16 | Inside cards |
| row-gap | 8 | Between rows inside a list |
| card-gap | 12 | Between cards in a section |
| section-gap | 24 | Between sections |
| row-h | 56 | Standard list row (56 = 44 target + 12 breathing) |
| row-h-compact | 48 | Supplement items, setting rows |
| control-h | 48 | Inputs, default buttons |
| hero-btn-h | 52 | Mark eaten, water quick-adds |

### 1.3 Corner radius

| Token | Value | Use |
| --- | --- | --- |
| radius-card | 14 | Cards, sheets' inner panels (keeps the current `--radius`) |
| radius-control | 10 | Buttons, inputs |
| radius-pill | 999 | Chips, segmented controls, status pills |
| radius-sheet | 20 | Bottom sheet top corners |

### 1.4 Card style

One card: `background: card; border: 1px solid border; radius 14; shadow: 0 1px 2px rgb(0 0 0 / 4%)`
in light mode, border only in dark mode. Cards are used for objects (a meal, the water tracker, a
grocery week). Lists of rows share one card with 1 px dividers. Sections are not cards: a section is
a heading plus content on the page background. The hero card is the only card allowed a stronger
border (2 px primary at 40 % alpha).

### 1.5 Button hierarchy

| Level | Look | Height | Where |
| --- | --- | --- | --- |
| Hero | filled success green, white text, 52 px, full width | 52 | Mark eaten only |
| Primary | filled primary blue, white text | 48 | One per screen: Shop, Save, Generate, Next |
| Tonal | primary tint background, primary text | 48 to 52 | Water quick-adds, preset chips |
| Outline | 1 px border, foreground text | 44 to 48 | Secondary actions: Review list, Cancel |
| Text | no background, primary text, 44 px hit area | 44 | Undo, Edit, This week |
| Destructive | filled red, only inside a confirmation sheet | 48 | Delete confirmations |

Rules: one primary per screen; the hero button never appears twice on a screen; pending state
shows a 16 px spinner in place of the icon and keeps the label; disabled is 50 % opacity and never
used for the primary daily actions (they stay enabled and fail with an error if offline).

### 1.6 Inputs

48 px tall, 10 px radius, 1 px border at 3:1 contrast (`oklch(0.66 0.012 260)`, `#8e929a` light;
`oklch(0.5 0.015 260)` dark), 16 px text, label above at 13 px 500, hint below at 13 px muted, error
below in red with an icon. Numeric fields use `inputMode="decimal"` and right-aligned tabular text
with the unit as a suffix inside the field ("3.10 | kg"). Time fields use the native picker,
rendered at full width in their own row (never two time inputs in one row at phone width). One
shared `DateTimeInput` component replaces the eight inline-styled `<input type="time">` copies.

### 1.7 Icons

Lucide, stroke 2, 20 px inside rows and buttons, 24 px in the navigation bar, 16 px inline with
text. Icons always sit next to a word except in three universal places: the "+" add button in
Shopping Mode, the back chevron, and the close X. Never use an icon alone to carry state.

### 1.8 Semantic colours

All values are oklch with the resolved hex for reference. Every text pair is at least 4.5:1 on its
intended background and every fill is at least 4.5:1 with white (light) or the dark background
(dark). State is always carried by a word or an icon as well.

| Meaning | Light text | Light fill | Light tint | Dark text | Dark fill | Dark tint | Icon / word |
| --- | --- | --- | --- | --- | --- | --- | --- |

| Pending | oklch(0.52 0.02 260) `#626975` | — | `#eff2f7` | `#9399a2` | — | `#1c2027` | circle, planned time |
| Upcoming / Next | primary `#2966cc` | primary | `#e6f3ff` | `#5a98f3` | `#5a98f3` | `#172846` | position + "NEXT" eyebrow |
| Missed / Overdue | oklch(0.5 0.19 27) `#b7191c` | `#cc2827` | `#ffebe7` | `#f66d67` | `#f66d67` | `#391a17` | alert-circle, "Overdue" |
| Training | primary `#2966cc` | primary | `#e6f3ff` | `#5a98f3` | `#5a98f3` | `#172846` | dumbbell, "Training day" |

Neutrals (light): background `#fafcff`, card `#ffffff`, foreground `#0c121a`, muted `#626975`,
border `#dee1e7`, secondary `#eff2f7`. Dark: background `#0a0d12`, card `#15181f`, foreground
`#f0f2f5`, muted `#9399a2`, border `#292e36`, secondary `#1c2027`.

What changes from today's tokens: light success and warning become darker for text and fills
(the tints stay light); Rest moves from sky blue to teal so it cannot be confused with the primary;
Training uses the primary so green means only "completed". Adherence band colours (great / good /
ok / poor) are used only on finished days in Week and History, never on the live Today screen.

### 1.9 Dark and light mode

Both themes are token-for-token complete (table above). Rules: never lighten by opacity (skipped
rows use the muted text colour, not 60 % opacity); tints are separate tokens per theme; charts take
their colours from tokens; the theme control stays in Settings as a labelled segmented control.

### 1.10 Touch targets and reachability

Minimum 44 × 44 px for anything tappable; 48 px for list rows; 52 px for Mark eaten and the two
water buttons. Header actions are 44 px. The three daily primaries (Mark eaten, +250 mL, +500 mL)
sit in the middle third of a 390 × 844 screen at page load. Sticky elements: the bottom
navigation, the sheet footer, the Shopping Mode counter. Nothing else is sticky.

### 1.11 Loading, empty, error and success states

| State | Treatment |
| --- | --- |
| Route loading | Skeleton of the page shape: header text block plus three card placeholders, 200 ms delay before showing so fast responses never flash |
| Action pending | Spinner replaces the icon inside the control; control stays the same size; row stays interactive for other rows |
| Optimistic | Completion, water, supplements and shopping ticks apply instantly; a failure reverts and shows the error toast |
| Empty | Title, one sentence, one primary button: "No meals planned for today." → "Open your plan"; "No grocery list yet." → "Generate this week's list"; "No prep session this week." → "Plan a prep session" |
| Error (action) | Toast at bottom-centre above the nav: "Couldn't save. Your change is still on screen." with "Try again". No technical words |
| Error (page) | Inline card: "This page couldn't load." with "Try again" and the bottom nav still usable |
| Success | Inline state change (the row flips), no toast, except when the result is off-screen ("List generated · 14 items") |
| Offline | Thin banner under the header: "Offline · showing your last synced plan"; queued actions later read "Saved on this device. Will sync when connected." |
| Confirmation | One sheet component: title as a question, one-sentence consequence, primary action named after the verb ("Delete list"), Cancel |

Behaviour:
- Header date opens Week view. "This week" is a text button, 44 px. No day stepper row; previous
  days open from Week, and a "Back to today" pill appears in the header when viewing another day.
- Segmented control: 48 px, two segments for the seeded plan; custom day types append segments
  up to three, then the control becomes a single "Training day ˅" chip that opens a sheet. Active
  segment is filled with the day-type colour at fill contrast, includes a check icon, and the day
  line states it in words.
- Day line: on a training day shows workout and time with "Edit"; with no workout recorded shows
  "Set workout" as a text button; on a rest day shows "Rest day · no training" and no workout row.
- Progress strip: three inline stats with thin 4 px bars, colours neutral (primary) during the day.
  Tapping opens the expanded summary sheet (kilocalories and macros in words, overall %).
- Hero: the next pending meal by time, or the earliest overdue one. Eyebrow shows "NEXT MEAL · in
  1 h 12 min" or "OVERDUE · 20 min ago" (warning text, not red). Purpose chip only when set.
  Ingredient rows: amount (tabular, 15 px 600) then name; grouped items show a "Swap" text button
  that opens a bottom sheet with the options. Caption "Training portions" or "Rest portions".
  "Mark eaten" 52 px. After tapping: card flips in place to "Eaten 5:33 PM · Edit · Undo", the
  strip updates, and after 400 ms the next meal animates into the hero.
- When all meals are done: hero becomes "All meals eaten · Nice work" with the day's supplement
  and water remainders; when no meals exist: empty state with "Open your plan".
- Water card: metric 28 px, thin bar, remaining text, two tonal 52 px buttons with the unit,
  "Undo 250 mL" text button appears after an add. Overflow "…" opens custom amount and today's
  entries. Reaching the target turns the bar success green and the remaining text to "Target
  reached".
- Meals list: 56 px rows. Left: state icon (check-circle green, circle muted, alert-circle for
  overdue, play-triangle for next). Middle: name, then secondary "8:00 AM → 8:05 AM" (planned →
  eaten) or "8:30 PM · After training". Right: chevron. Tapping expands the row in place to the
  meal detail (2.2). Skipped: "Skipped" word chip in muted colour, no opacity.
- Supplements: group rows show the timing and remaining count; the first group with remaining
  items is expanded by default. Item rows 48 px with a 28 px checkbox on the left, name and dose,
  optional time. "Take all" text button on the expanded group's header.
- Reminder strip: one row, 44 px, bell icon, up to two reminders joined with "·", "and 1 more"
  when longer; tap opens a reminder sheet. Meal and supplement reminders are not shown here; they
  appear as the overdue state on their own rows.
- Note row: 44 px "Add a note about today" opens the note and check-in sheet.

Page height target at 390 px with five meals and eight supplements: under 2,000 px (currently
3,461 px). First tappable primary at open: Mark eaten at about y = 520 on a 390 × 844 screen.

Tablet and desktop (≥ 1024 px): two columns, 8 / 4: left column day state, hero, meals; right
column water, supplements, reminders, note. Navigation becomes a 220 px left rail with the same
five items.

### 2.3 Training / Rest selector

Segmented control, full width, 48 px, pill radius, 4 px inner padding, segments equal width.
Labels are words only ("Training", "Rest"); the active segment is filled (Training: primary; Rest:
teal fill) with white text and a leading check icon; inactive segments are muted text on the
secondary background. The day line beneath restates the choice in words so the state is never
colour-only.

Interaction:
1. Tap an inactive segment.
2. If no meal today is COMPLETED or SKIPPED: switch immediately (optimistic), rows update their
   amounts with a 200 ms crossfade, the day line reads "Rest day · no training".
3. If any meal is logged: open a confirmation sheet:
   - Title: "Switch to a rest day?"
   - Body: "2 meals are already logged as eaten. Rest-day portions will apply to the 3 remaining
     meals."
   - Primary: "Keep eaten meals as logged" (recommended)
   - Outline: "Change all 5 meals to rest portions"
   - Text: "Cancel"
   Either choice keeps completion status and times; the outline choice also rewrites the
   quantities of logged meals, which is what the current code does silently.
4. The weekly schedule is never changed from here; one sentence under the control says "Today
   only. Your weekly schedule is unchanged."

Custom day types: up to three segments; beyond three, a single chip "Training day ˅" opens a sheet
listing all types with their colour dot and name.

### 2.4 Workout selector

Entry: the day line's "Set workout" or "Edit" text button (Today), or the workout name on the
Week view.

Sheet "Today's workout":

```
PRESETS
( Push ) ( Pull ) ( Legs ) ( Upper ) ( Lower ) ( Full body )
BODY PARTS
( Chest ✓ ) ( Shoulders ✓ ) ( Triceps ✓ ) ( Back ) ( Biceps )
( Quads ) ( Hamstrings ) ( Glutes ) ( Calves ) ( Core )
Chest + Shoulders + Triceps
▸ More: session name, training time (7:30 PM)
[ Cancel ]            [ Save workout ]
```

- Presets are single-select chips that set the body parts (Push = Chest, Shoulders, Triceps; Pull =
  Back, Biceps; Legs = Quads, Hamstrings, Glutes, Calves; Upper, Lower, Full body accordingly).
  The mapping is editable under Plan → Training days & workouts. Tapping a preset changes the
  primary button to "Use Push"; a second tap saves. Two taps total.
- Body parts are multi-select 44 px chips; custom labels are added with "+ Add" at the end of the
  row (text field inline).
- "More" disclosure holds the optional session name and the training time. The training time
  field explains its side effect ("Meals re-time around this") and saves with the sheet, not on
  change.
- "Use this weekday's usual workout" becomes a preset chip "Usual (Chest + Triceps)" at the front
  of the presets row when the weekday has one.
- Selecting nothing and saving clears the workout; "Clear" is not a separate destructive button.

### 2.5 Water

Card, 16 px padding:
- Row 1: "Water" label (13 px 600 muted) left, metric "1.5 / 4.0 L" right (28 px 600 tabular, the
  target in muted).
- Row 2: 6 px progress bar, primary fill; success fill when the target is reached.
- Row 3: "2.5 L to go" secondary; when over target "Target reached · 4.3 L".
- Row 4: two tonal buttons "+250 mL" and "+500 mL", 52 px, equal width, 8 px gap, plus a 44 px
  "…" outline button for custom amount and today's entries.
- After a tap: the metric increments immediately, the bar animates 300 ms, and a text button "Undo
  250 mL" appears in row 3 for ten seconds, then moves into the "…" sheet.
- Duplicate detection (same amount within ten seconds) stays, surfaced as an inline question in row
  3: "Same amount again? Add · Dismiss", not a toast.
- The quick amounts remain configurable in Settings; the buttons always show the unit.

### 2.6 Supplements

Section "SUPPLEMENTS · 4 / 7" with a "Take all" text button on the right when items remain.

Group rows (48 px): timing label left ("Morning", "Pre-workout", "Before bed"), status right:
"all taken ✓" (success text) or "1 left" (foreground). Groups are collapsible; expanded by default
for the first group with remaining items, and for any group whose time has passed with items
left. A group whose items are all taken collapses automatically.

Item rows (48 px): 28 px checkbox left (44 px hit area), name 15 px, dose and time secondary
("5 g · 5:00 PM"), whole row tappable. Optimistic check with a 150 ms fill; no toast; the group
count updates. Missed items after their time show the warning icon before the checkbox and the
word "Missed" in the secondary line; the row still ticks with one tap.

Eight supplements collapse to three group rows (144 px) instead of eight item rows (450 px).

## 4. Responsive rules

- 320 px: every layout in this document was checked to wrap, not overflow. Two-button rows stack
  when the buttons' text would wrap ("+250 mL" fits; longer custom amounts stack).
- 375 to 430 px: reference layouts.
- ≥ 768 px: page column max 720 px, bottom nav remains.
- ≥ 1024 px: left rail navigation, Today in two columns, Plan editor with meal list and detail side
  by side, sheets become centred dialogs (already the case).
- Text at 160 %: rows wrap to two lines, stats strip wraps to three rows, the hero ingredient list
  keeps amount and name on one line by allowing the name to wrap under the amount.
